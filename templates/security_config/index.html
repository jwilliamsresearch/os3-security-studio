Security Misconfiguration

What is it? Security misconfigurations occur when security settings are not properly implemented, creating vulnerabilities.

Common Misconfigurations:
  • Default credentials: admin/admin, root/root
  • Missing security headers: No HTTPS, CSP, HSTS
  • Unnecessary features: Debug mode, directory listing
  • Outdated software: Unpatched frameworks
Security Headers:
  • HSTS: Enforce HTTPS connections
  • CSP: Content Security Policy
  • X-Frame-Options: Prevent clickjacking
  • X-Content-Type-Options: MIME sniffing protection
Prevention:
  • Security hardening checklists
  • Regular security audits
  • Automated configuration management
  • Security header implementation

Configuration Issues

Common security misconfigurations found in web applications:

Application Level:
  • Debug mode enabled in production
  • Default credentials not changed
  • Unnecessary services running
  • Verbose error messages
Server Level:
  • Missing security headers
  • Outdated software versions
  • Open ports and services
  • Weak SSL/TLS configuration
Learning Objectives
  • Identify common security misconfigurations
  • Learn to implement security headers
  • Understand the importance of secure defaults
  • Practice security hardening techniques
Security Hardening Checklist
✅ Application Security:
  • Change default credentials
  • Disable debug mode in production
  • Implement proper error handling
  • Use secure session configuration
  • Enable security headers
✅ Server Security:
  • Keep software updated
  • Close unnecessary ports
  • Configure proper SSL/TLS
  • Implement rate limiting
  • Regular security audits
