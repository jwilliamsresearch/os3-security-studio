Security Headers Analysis

This page demonstrates security headers implementation. Check your browser's developer tools to see the headers.

Security Headers Status

The following security headers are implemented for secure endpoints:

Header Value Purpose Status
X-Content-Type-Options nosniff Prevents MIME sniffing attacks ✓ Active
X-Frame-Options DENY Prevents clickjacking attacks ✓ Active
X-XSS-Protection 1; mode=block Enables XSS filtering in browsers ✓ Active
Strict-Transport-Security max-age=31536000; includeSubDomains Enforces HTTPS connections ✓ Active
Content-Security-Policy default-src 'self' Controls resource loading ✓ Active
How to Check Headers
  1. Open browser developer tools (F12)
  2. Go to Network tab
  3. Refresh this page
  4. Click on the request to this page
  5. Check the Response Headers section
Implementation
Security Headers Code:
@app.after_request
def after_request(response):
  if 'secure' in request.endpoint:
    response.headers['X-Content-Type-Options'] = 'nosniff'
    response.headers['X-Frame-Options'] = 'DENY'
    response.headers['X-XSS-Protection'] = '1; mode=block'
    response.headers['Strict-Transport-Security'] = 'max-age=31536000'
    response.headers['Content-Security-Policy'] = "default-src 'self'"
  return response
Header Benefits:
  • HSTS: Prevents protocol downgrade attacks
  • CSP: Mitigates XSS and injection attacks
  • X-Frame-Options: Stops clickjacking
  • X-Content-Type: Blocks MIME confusion
Missing Headers

For insecure endpoints, these headers are missing:

  • No HSTS enforcement
  • No CSP protection
  • No frame protection
  • No MIME type enforcement

Compare by checking headers on insecure demo pages.
