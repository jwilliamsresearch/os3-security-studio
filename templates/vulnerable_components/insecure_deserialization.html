Insecure Deserialization

Security Risk: Unsafe deserialization can lead to remote code execution, authentication bypass, and data tampering.

Dangerous Functions:
  • yaml.load(): Can execute arbitrary Python code
  • pickle.loads(): Can run malicious payloads
  • eval(): Direct code execution
  • exec(): Execute arbitrary commands
Safe Alternatives:
  • yaml.safe_load(): Safe YAML parsing
  • json.loads(): JSON is safer than pickle
  • ast.literal_eval(): Safe evaluation
  • Input validation: Validate all untrusted data

Malicious YAML:

# Or this for subprocess execution

- [["whoami"]]
Malicious Pickle:
# Python code to create malicious pickle
import pickle, os
class Exploit(object):
  def __reduce__(self):
    return (os.system, ('echo pwned',))
pickle.dumps(Exploit())
Security Best Practices
Safe Deserialization
  • Use yaml.safe_load() instead of yaml.load()
  • Prefer JSON over pickle for data exchange
  • Use ast.literal_eval() for safe evaluation
  • Validate all input data before processing
What to Avoid
  • Never use pickle with untrusted data
  • Avoid eval() and exec() with user input
  • Don't use yaml.load() without safe loader
  • Never deserialize signed but unencrypted data
Additional Protection
  • Run deserialization in sandboxed environments
  • Implement integrity checks (HMAC)
  • Use type checking and validation
  • Monitor for unusual system calls
